### Backend requirements (FR-DEL-003 to 008; Flow 3; AT-17 to 20, 25)
All endpoints role COURIER unless stated; anything not assigned to the caller is **404**.
1. **`GET /api/v1/courier/deliveries?scope=today|active|completed`** (default `today`; `completed` paginated) via `CourierDeliveryQueries.listForCourier`; items `parcelId, trackingNumber, status, pickupCity, dropoffCity, originDistrictName, destinationDistrictName, assignedAt`.
2. **`GET /api/v1/courier/deliveries/{parcelId}`:** load the local `deliveries` row with `courier_id = caller` first (else 404); fetch parcel details from parcel-service `GET /internal/v1/parcels/{id}` through `ParcelClient` (`InternalRestClientFactory`, base `PARCEL_SERVICE_URL`); return the parcel view **without fees**: contact names, phones, addresses, instructions, size, weight, description, zones, plus `status`, `allowedNextStatuses`, `allowedFailureReasons[{code, label}]` and the proof if delivered. `allowedNextStatuses`: `CREATED → [PICKED_UP, FAILED]`, `PICKED_UP → [IN_TRANSIT, FAILED]`, `IN_TRANSIT → [OUT_FOR_DELIVERY, FAILED]`, `OUT_FOR_DELIVERY → [DELIVERED, FAILED]`, terminal → `[]`; failure reasons per Table 2.4 by stage (`FailureReason.allowedFor`).
3. **`POST /api/v1/courier/deliveries/{parcelId}/status`** (`multipart/form-data`: `status`, `note?`, `recipientName?`, `failureReason?`, `photo?`), **exactly Flow 3**: in one local transaction: (a) take the pessimistic write lock on the `deliveries` row where `courier_id` = caller (else 404, also for unassigned parcels); (b) validate: transition legal from the local status (409 `INVALID_STATUS_TRANSITION`), `DELIVERED` needs `recipientName` 2-100, `note` up to 500, `FAILED` needs a reason allowed for the stage, `OTHER` needs a note of 5-500, **photo only with `DELIVERED`** (else 400), photo per FR-DEL-006; (c) if `DELIVERED` insert `delivery_proofs` (and `proof_photos` when a photo is sent; `has_photo` accordingly); (d) call parcel-service `POST /internal/v1/parcels/{id}/transition` with `{toStatus, actorUserId = courier id, actorRole: "COURIER", note, failureReason, recipientName}`; (e) on success update the local delivery row (status, sequence from the response, `terminal_at` when terminal) and commit; (f) if the call answers **409, 5xx or times out**, the transition may nevertheless have been applied: re-read `GET /internal/v1/parcels/{id}` and compare. If the parcel already has the requested status **and** `statusSequence` = local sequence + 1, treat it as success (commit proof rows and delivery row, normal success response; use the parcel's `updatedAt` as `statusChangedAt`); in every other case roll back the whole local transaction (**no proof for a transition that did not happen**) and return the error (409 codes such as `INVALID_STATUS_TRANSITION` and `CONCURRENT_UPDATE` keep their code, anything else 503 `SERVICE_UNAVAILABLE`). Response `{parcelId, status, sequence, statusChangedAt}`. A courier can add an optional note to any transition (visible to owner and admins, never on the public view; never log it).
4. **Photo (FR-DEL-006, NFR-SEC-014):** accept JPEG or PNG by **content inspection** (magic bytes + `ImageIO`, not file name or declared type); upload limit `MAX_UPLOAD_MB` (10) → 413 `PAYLOAD_TOO_LARGE`; other content → 415 `UNSUPPORTED_MEDIA_TYPE`; guard against decompression bombs (reject absurd pixel counts before decoding); re-encode to **JPEG quality 0.8** with the longest side at most 1600 px (scale down only; composite PNG transparency on white; metadata stripped); the stored image must be at most `MAX_STORED_PHOTO_MB` (5) else 413; store in `proof_photos` (`content_type` always `image/jpeg`).
5. **Proof endpoints (FR-DEL-007, BR-06):** `GET /api/v1/proofs/{parcelId}` → `{recipientName, note, hasPhoto, capturedAt}`; `GET /api/v1/proofs/{parcelId}/photo` → `image/jpeg` with `Cache-Control: no-store` (load the BYTEA only here). Allowed: owner customer (`customer_id = sub`), owner merchant (`merchant_id = mid`), the assigned courier, any admin; everyone else and "no proof" → 404. Proofs are never modified after writing.
6. **FR-DEL-008:** a courier can never read or change unassigned or another courier's parcels (404) and cannot cancel (no endpoint); couriers on customer, merchant or admin endpoints get 403 from the role rules.
7. Security: `@PreAuthorize` roles, client tokens 403 (common-lib), OpenAPI annotations, DTOs and MapStruct, no personal data in logs (mask phones), the note never logged.
