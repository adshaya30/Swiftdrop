## 2. Decision & Recommendation Summary

### Backend (`backend/auth-service`): **Fix in place**
- **Reasoning:** The business logic (BCrypt, token rotation, family compromise detection, concurrent grace window, lockout counters, JPA queries, and integration tests) is already well-implemented and passes tests. The required changes are structural and naming alignments:
  - Consolidating migrations V1..V8 into `V1__init.sql`.
  - Reorganizing packages using `git mv` into slice-first (`auth.login.*`) and `auth.domain`.
  - Adding `SecurityRules`, `PasswordPolicy`, `PasswordHasher`, and `RefreshCookieFactory`.
  - Replacing `application.properties` with standard `application.yml` (port 8081).
  - Normalizing method names in `JwtService` and `RefreshTokenService` to match master prompt 8.1.
- **Verdict:** Do NOT rewrite. Fix in place through small pull requests.

### Frontend (`frontend/`): **Rebuild foundation files**
- **Reasoning:** The current frontend was built using TypeScript, Tailwind CSS, Axios, and custom non-MUI markup, whereas the platform standard specified across all member prompts is **JavaScript (JSX), MUI v5/v6, TanStack Query, React Hook Form + Zod, and Vitest**.
  - All other members (#2 through #10) are required by master 8.1 to import `{ apiRequest, apiForm, apiBlob, ApiError }` from `src/api/http.js`, `{ useAuth }` from `src/context/AuthContext.jsx`, shared components (`StatusChip`, `LoadingState`, etc.) from `src/components/`, and rely on the centralized `src/routes/routeTable.js` with dynamic `import.meta.glob` resolution.
- **Verdict:** Retain the repository structure, but rebuild the core frontend foundation files in `src/` to match master 8.1 and Prompt 2 specifications.
